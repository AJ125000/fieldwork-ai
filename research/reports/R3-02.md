## 1b. Jev assessment
| Item | Finding | Source |
|---|---|---|
| What | A "System One" model: it takes unstructured state plus typed questions. It returns yes/no confidences, choice probabilities (up to 255 options) and scores, all in one parallel pass. It generates no text. | https://typesafe.ai/blog/introducing-system-one-models-and-jev (fetched) |
| Launch | Early access 15 Sep 2026, waitlist, $40M seed led by DCVC | same; width.ai (fetched) |
| Cost and speed | $0.042 per million input tokens, output free. 70 to 500 ms end to end. The vendor says it cannot prove the price isn't subsidised. | typesafe.ai; width.ai |
| Access | Closed hosted API at api.typesafe.ai, with Python and JS SDKs. No open weights. Google Cloud or Vertex availability is **not stated**. | typesafe.ai; width.ai |
| Inputs | **Text only for now.** Images are "not yet". It cannot read the photos itself. | typesafe.ai |
| Weaknesses | No reliable arithmetic or date comparison. It reads instructions literally. Accuracy drops with irrelevant detail. The LangChain integration is "experimental". | width.ai |

**Verdict:**
- It does not change the stack, because the core job is reading photos and Jev has no vision.
- It could only act as a text-based router or calibrated judge, for example "is this claim consistent with these extracted findings?".
- It is a closed third-party API outside Google Cloud and waitlist-gated, so it is risky for a hackathon.
- If the Gemini/Gemma rule is real, Jev can at most be an optional extra. Do not make it load-bearing, and do not call it the AI component.
- Early access, a waitlist and a possibly subsidised price add risk.

**Same "fast, calibrated, typed decision" pattern on Google tools:**
1. **Gemini 3.5 Flash-Lite with structured output.** Use a JSON schema with enums and a numeric confidence per field. Input is $0.30 per million tokens for text, image and video, and output is $2.50. https://ai.google.dev/gemini-api/docs/pricing (fetched). If the API exposes logprobs, use them for real probabilities (not verified here). Model self-reported confidence is poorly calibrated, so calibrate it on a held-out set.
2. **Calibrated classifier on embeddings.** Create Gemini Embedding 2 vectors from listing and complaint photos, train a logistic or boosted model in BigQuery ML or Vertex AI, and apply Platt scaling or isotonic calibration. This gives true probabilities in milliseconds for pennies. It needs labelled data, which is the catch for a hackathon.
3. **Fine-tune Gemma 4** on Vertex to emit schema-constrained verdicts. This is heavier and probably overkill for a hackathon.

Best hackathon choice: option 1 for the demo, plus a small calibration table to show the confidences are meaningful.

## 3. Photo authenticity
| Tool | Notes | Source |
|---|---|---|
| C2PA | Pixel 10 signs every JPEG at capture. Google Photos shows credentials in its About panel. Samsung Galaxy S25 adds C2PA metadata for AI edits. YouTube applies labels from the manifest (May 2026). This is the strongest positive signal, but absence proves nothing because most phones don't sign and metadata is stripped on upload. Use the `c2pa-python` or `c2pa-rs` open-source SDKs to read it. | securityaffairs.com, c2paviewer.com (snippet-only) |
| TruFor | Open source forgery localisation from GRIP-UNINA. It gives an integrity score, a pixel map and a reliability map. Still the best-known baseline. I found no 2026 successor. | https://grip-unina.github.io/TruFor/ (snippet-only) |
| AI-image detectors | Candidates are SIDA, AIDE, UnivFD and Community Forensics. The NTIRE 2026 challenge, AI-GenBench and AIGIBench show detectors fail on recompression, resizing and unseen generators. | https://arxiv.org/pdf/2504.20865 (snippet-only) |

Treat all detector outputs as a **risk signal, not a verdict**. Combine four signals: C2PA presence, SynthID, TruFor, and EXIF or duplicate-image checks. Add a Gemini check for inconsistent lighting, shadows or text.

## 5. Other building blocks
- **Same-item matching.** Compare Gemini Embedding 2 vectors of the listing photo and the complaint photo. DINOv3 is the open alternative, with a custom but commercial-use licence (snippet-only). It does well on instance retrieval, so run a small test on your own photo pairs to pick one.
- **OCR and documents.** Gemini reads receipts, IMEI labels and serial numbers directly. Embedding 2 accepts PDFs of up to 6 pages.
- **Multilingual grades.** Gemini handles it. Gemini 3.5 Live Translate (70+ languages) is in preview.
- **Evaluation.** ADK 2.10 and later have eval metrics for token use and model calls. Build a small labelled set of listing and complaint pairs. Track accuracy, calibration and false-accuse rate.
