## Strengths and weaknesses by stage

| Stage | Demonstrated strength | Current weakness and implication |
|---|---|---|
| Seller capture | Video/photos produce retained frames, a condition record and translated listings. The earlier live functional smoke exercised these routes. | Sharpness ranking and time spacing do not establish front/back/label/cuff coverage. Brightness filtering does not reject every blurry take. The capture code is client generated; seeing it is not proof of fresh, authentic media. |
| Claims and listing | Claims distinguish shown, measured, declared and cannot-judge information. Evidence links can support inspection. | Citation validity cannot prove a claim's meaning is correct. Free-form listing prose and translations need independent checks against the claims. The seller UI publishes automatically after capture; draft correction/approval and seller declarations are missing. |
| Grade and defect heads | Full source audit, recovered defect labels, separate fitting/validation/calibration groups and saved comparisons make the experiment reproducible. | Grade quality is weak; front-only public images do not match phone-video views. Garment-level sorter labels may describe defects outside the visible front. Higher exact accuracy alone does not justify promoting a candidate. |
| Buyer search and answers | Structured filters, claim citations and explicit unknown states are implemented. Ten live question fixtures produced the expected states. | Ten state checks do not establish semantic correctness. Search excludes recorded defects, which does not prove their absence elsewhere. Minimum-grade filtering currently accepts an item if the highest member of its broad grade set meets the filter; this is an optimistic interpretation. |
| Agents and purchase | Buyer/seller agents work in the earlier functional smoke. Central escrow guards enforce positive amount, currency and seller price constraints. Usage logging includes ADK responses. | Purchase confirmation is an agent instruction rather than a separate programmatic consent boundary. Buyer MCP tools lack a seller-quote tool. Model fallback after any exception can repeat work; purchases need idempotency before robust retries. |
| Received-frame matching | SigLIP matched 12/12 known transformed copies in a closed set. | This is not an identity benchmark. Independent best matches can reuse a received frame for several seller views. Similar-looking garments and unseen views remain untested. The 0.6 cutoff is not calibrated on real paired captures. |

Insufficient valid diff area currently returns no proposals, indistinguishable from no detected change. |

A judge cannot detect a defect it never receives, and posthoc checks are not unbiased accuracy estimates. |

## Improvements implemented in this review

1. **Preserve alignment evidence:** reference-specific output names prevent one received frame's later alignment from overwriting an earlier comparison. A real OpenCV regression uses two different references with identical basenames and one received image; it checks that the first result remains unchanged.
2. **Remove unsupported answer wording:** when a model claims shown but supplies no admissible claim citation, the code replaces the answer as well as downgrading its state. The deterministic fallback is English and explicitly labels `lang=en`. Answer states are constrained to the three supported values; unknown answers carry no evidence citations. This validates citation structure, not semantic entailment.
3. **Validate crop geometry:** out-of-range, inverted and zero-area boxes are discarded during draft ingestion; shown claims without remaining evidence are demoted. Crop generation rejects malformed boxes. Existing stored records remain readable without a schema migration.
4. **Respect uncheckable listed flaws:** if a listed flaw has no usable aligned evidence, the assessment cannot remain consistent merely because another comparison found no change. It becomes inconclusive unless another finding already supports differs, and the report records the limitation.

Validation: **77 focused tests passed**, including 14 new evidence-integrity cases; **12 legacy harness tests passed in a separate process**. These are software checks. No claim of improved real-garment accuracy or latency follows from them. ConditionRecord, Store and successful API response shapes remain unchanged.

## Ordered improvement work

1. **Capture coverage and seller review.** Track visible/unclear/missing garment regions, show targeted retake guidance and give sellers a draft review before publication. Keep seller declarations separate from visible evidence. Do not turn an uncalibrated blur cutoff into an automatic garment-quality verdict. Validate on dark/plain fabrics as well as patterned ones.
2. **Make comparison coverage explicit.** Distinguish insufficient overlap from no candidate change, report unique received-view coverage, and test similar-looking different garments. Preserve uncertainty when evidence is missing. Calibrate pairing and DINO thresholds on real development/calibration pairs only.
3. **Measure workflow speed and retry behavior.** Add stage timings and request tracing, then measure warm/cold latency and failure rates over repeated representative cases. Cache repeated embeddings within an inspection and consider bounded concurrent crop calls after profiling. Add purchase idempotency and a programmatic confirmation boundary before expanding agent retries.
4. **Improve defect supervision before enlarging models.** Obtain labels for defects actually visible in an image/crop, including small holes, clean negatives, backs and close-ups. Compare higher-resolution/patch features and classifier alternatives using validation selection; retain a locked test split. Avoid tuning repeatedly against the already inspected public test set.
5. **Run the real-capture benchmark.** Record and independently annotate development/calibration/test garments using CAPTURE-GUIDE.md and the prepared capture kit. Measure seller claim correctness/coverage, pairing errors, alignment coverage, proposal recall, crop judgment errors/abstention, answer grounding, report usefulness, human agreement, and full workflow latency/token usage. Count failed/abstained cases in denominators. Include unchanged re-shoots, added defects, changed lighting, similar garment swaps, missing views and unusable captures.
6. **Complete manual local acceptance, then cloud validation.** Test seller → buyer → All good and seller → buyer → raise issue → request evidence → human decision. Before broader usage, add ownership checks, inventory reservation and transactional state changes. Verify persistence/restarts in the eventual cloud deployment.

No real captures are available yet. They are required to validate these model and threshold improvements, but do not prevent the software improvements above. The present public front-only data cannot substitute for real seller-versus-received ground truth.
